# AgentStreamDeck v3.0.5

[Project overview](../../README.md) · [Documentation index](../README.md)

Normal pip upgrades can now activate themselves while the broker is running.

- Checks local installed-wheel metadata every five seconds, independently of online PyPI checks.
- Waits for pip to finish and for ten seconds of stable metadata. Validates installed RECORD hashes and imports the new package and dependencies in a fresh interpreter before restarting.
- Shares an update lock with Jelly's red `!` button to avoid overlapping installs/restarts.
- Preserves custom `OCDECK_HOME` and mock mode across detached restarts. Uses the existing systemd restart policy when running under the installed Linux service.
- Leaves the current broker running when verification or restart-helper launch fails. The helper never launches a second broker if the original has not exited within its bounded wait.
- Adds `auto_restart_on_upgrade` (default true for real brokers) and upgrade-watcher status/logging. Source/editable installations are excluded.

One-time transition: v3.0.4 and older must restart once to load this watcher. Jelly's existing update button handles that automatically. Later pip upgrades need no separate restart when the watcher-enabled broker is running in the updated Python environment. Pip alone does not bootstrap or start a stopped broker.

Includes unit coverage of incomplete installs, rollback, import failures, launch failures, custom homes and debounce timing, plus a real wheel-to-wheel pip upgrade test using an isolated mock broker.
