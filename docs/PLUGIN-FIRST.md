# Plugin-first setup\n\n          AgentStreamDeck does not need to launch your AI harness. The broker is a per-user background process, and each supported harness reports lifecycle metadata through its native plugin/hook system.\n\n          ## 1. Install the broker\n\n          ```text\n          python -m pip install --upgrade agentstreamdeck\n          ocdeck install\n          ```\n\n          Windows installs an **AgentStreamDeck Broker** Scheduled Task at interactive logon and starts it immediately. Linux installs and enables the `agentstreamdeck.service` systemd user service. OpenCode's global server plugin is installed automatically when `opencode` is on PATH.\n\n          ## 2. Install harness hooks\n\n          From the software project you work in:\n\n          ```text\n          ocdeck harness-install claude\n          ocdeck harness-install codex\n          ocdeck harness-install copilot-cli\n          ocdeck harness-install copilot-vscode\n          ocdeck harness-install gemini\n          ocdeck harness-install cursor\n          ```\n\n          Install only the profiles you use. Existing config is merged, unrelated hooks are preserved, and AgentStreamDeck writes backups/receipts.\n\n          ## 3. Launch normally\n\n          Start `claude`, `codex`, `copilot`, `gemini`, `agent`, VS Code, OpenCode, a BAT file, or your own local-model wrapper exactly as you normally would. Native hook processes authenticate to the broker over loopback and send only bounded lifecycle metadata. Prompts, tool output and transcripts are not forwarded.\n\n          The old `ocdeck start`, `harness-launch`, and `Launch-*.bat` paths are optional compatibility helpers. They are not required for monitoring.\n\n          ## 4. Verify\n\n          Run `ocdeck status`. `device.input_events` increments for physical key down/up events and `device.last_input` shows the most recent key. On Windows, pressing an assigned agent key restores/focuses the captured containing window. Keep one monitored harness per OS window when reliable one-touch focus matters; several tabs sharing one Windows Terminal process cannot always be distinguished by Windows APIs.\n
